# Ayonix Zoomer 製品要件定義

## 1. 目的

Zoomを使ったオンライン研修で人手に依存している本人確認と受講監視を自動化し、管理者の運用工数を削減しながら監査可能な証跡を残す。

## 2. 利用者

- システム管理者: 組織設定、権限、保存期間、連携設定
- 研修管理者: 研修作成、受講者割当、監視、アラート確認、証跡出力
- 監査担当者: 読取専用でイベント・証跡・操作ログを確認
- 受講者: 開始前本人確認、カメラ同意、研修中の状態確認

## 3. 必須機能

### 3.1 受講者登録

- 受講者ID、氏名、所属、メールアドレスを登録
- 顔画像をアップロードまたはWebカメラで撮影
- 顔検出、正面度、照度、ブレ、解像度、遮蔽を品質判定
- 顔特徴量を暗号化保存し、原画像保存はポリシーで選択
- CSV一括登録、重複検知、登録更新、論理削除

### 3.2 研修開始前本人確認

- 研修URLからZoomer受講画面へ誘導
- カメラ利用、顔情報処理、証跡保存について同意取得
- 登録顔とライブ画像を1:1照合
- なりすまし対策として受動的／能動的ライブネス確認
- 不一致・低品質時は再試行し、上限超過時は管理者確認へ送る

### 3.3 継続認証

- 設定間隔で顔を再検出・再照合
- 一時的な低品質や姿勢変化を単発アラートにせず、連続判定で確定
- 判定結果は時刻、照合スコア、品質値、ルールバージョンとともに記録

### 3.4 受講状態検知

- 離席: 顔未検出が設定秒数継続
- 複数人: 2名以上の顔を設定フレーム数以上検出
- 居眠り疑い: 閉眼状態が設定秒数継続
- カメラ遮蔽・停止・タブ終了・ネットワーク断を別イベントとして分類
- 居眠りは確定判定ではなく「疑い」として管理者確認を必須化

### 3.5 アラート

- 画面内、メール、Microsoft Teams、Webhook
- 重要度、研修、受講者、イベント種別で通知ルールを設定
- 確認、誤検知、エスカレーション、コメント、担当者割当
- 同一イベントの重複通知を抑制

### 3.6 証跡・ログ

- 異常検知時の前後画像、設定間隔の定期画像、判定メタデータを保存
- 研修、期間、受講者、イベント、状態で検索
- CSV、PDF監査レポート、画像付きZIPを権限に応じて出力
- 閲覧・出力・削除操作を監査ログへ記録
- 保存期間満了後に自動削除

### 3.7 ダッシュボード

- 本日の研修、接続数、正常受講数、要確認数、未接続数
- 本人確認率、アラート推移、最新アラート
- 進行中研修からライブ監視へ直接遷移

### 3.8 設定

- 認証間隔、顔一致しきい値、離席秒数、閉眼秒数、証跡保存間隔
- 通知先、保存期間、画質、帯域上限
- 組織、ユーザー、ロール、SSO、Zoom OAuth、APIキー
- ライト／ダーク、言語（日本語／英語）

## 4. 状態モデル

- `PRECHECK_PENDING`: 本人確認前
- `VERIFIED`: 本人確認済み
- `MONITORING`: 継続監視中
- `WARNING`: 短時間の異常候補
- `ALERT`: 設定条件を満たした異常
- `REVIEWED`: 管理者確認済み
- `DISCONNECTED`: 接続断
- `COMPLETED`: 研修完了

## 5. 非機能要件

- 管理画面P95 API応答: 500ms未満（画像取得を除く）
- アラート反映: 検知確定後3秒以内
- 可用性: 月間99.9%
- 受講者1,000名同時監視を水平スケール可能
- 日本語UI、PC・タブレット対応、WCAG 2.2 AAを目標
- 全時刻はUTC保存、画面表示は組織タイムゾーン

## 6. 受入条件

- 登録顔とWebカメラ映像で本人確認が完了する
- 設定された閾値を超える離席・複数人・閉眼でアラートが作成される
- 異常検知時に証跡画像と判定メタデータが紐づく
- 管理者がアラートを確認済み／誤検知へ変更できる
- 保存期限後に画像が削除され、削除ログが残る
- 権限のないユーザーは顔画像・証跡を閲覧・出力できない
