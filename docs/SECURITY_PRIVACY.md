# セキュリティ・プライバシー設計

## 1. 基本原則

- 生体情報は目的を限定し、取得前に明示同意を得る
- 原画像の保存を最小化し、可能な限り端末内で特徴抽出・推論
- 顔特徴量はパスワードと同様に再発行できない高機密データとして扱う
- 自動判定だけで受講失格にせず、管理者の人手確認を残す

## 2. 技術対策

- 通信: TLS 1.3、HSTS、証明書自動更新
- 保存: KMS管理鍵、テナント別データ鍵、定期ローテーション
- 認証: SSO、MFA、短命アクセストークン
- 権限: 最小権限RBAC、顔画像閲覧と出力を別権限に分離
- セッション: Secure/HttpOnly/SameSite Cookie、CSRF対策
- API: Schema validation、WAF、レート制限、冪等性、リプレイ対策
- 証跡: 改ざん検知ハッシュ、署名URL、有効期限60秒以内
- 監査: ログイン、設定変更、画像閲覧、出力、削除を記録
- 開発: SAST、依存関係スキャン、秘密情報スキャン、SBOM

## 3. データ保持

- 顔特徴量: 契約・同意期間内のみ
- 証跡画像: 組織設定（推奨30〜90日）
- 監査ログ: 推奨1年、画像URLや顔特徴量は含めない
- 削除要求: 受理、承認、削除、バックアップ失効を追跡

## 4. 誤検知対応

- 居眠りは「居眠り疑い」として通知
- 眼鏡、照明、ネットワーク低下、顔向きによる品質低下を区別
- 連続フレームと時間窓で判定し、単一フレームでは確定しない
- 管理者が誤検知理由を分類し、モデル評価データへ匿名集計

## 5. 導入前に顧客と確定する項目

- 個人情報取扱い・生体情報同意文面
- 保存対象、保存期間、閲覧権限、削除手順
- 居眠り疑い等の扱いと不利益処分への利用可否
- 日本国内保存の要否、委託先、国外移転
- インシデント通知、監査対応、退職・受講終了時の削除
