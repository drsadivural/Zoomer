# テスト・受入計画

## 1. 機能テスト

1. 正常な顔画像を登録し、品質合格になること
2. 顔なし、複数顔、暗所、強いブレで再撮影要求になること
3. 登録本人が開始前照合を通過すること
4. 別人が照合失敗し、管理者確認へ送られること
5. 設定秒数を超える顔未検出で離席アラートになること
6. 2名以上の継続検出で複数人アラートになること
7. 閉眼が設定秒数継続した場合のみ居眠り疑いになること
8. 異常検知時に画像、時刻、受講者、ルール、モデル版が紐づくこと
9. アラートの確認済み・誤検知・担当者変更が監査ログへ残ること
10. 保存期限後に証跡が削除されること

## 2. 精度評価

- 顔照合: FAR/FRRを顧客データ条件で測定
- 離席: 検出遅延、再着席復帰時間
- 複数人: 遮蔽、背景写真、画面内写真への耐性
- 閉眼: 眼鏡、横顔、暗所、人種・年齢差による性能差
- ライブネス: 写真、スマホ再生、画面表示、簡易マスク

本番しきい値は評価結果から決め、UIのサンプル値をそのまま採用しない。

## 3. 性能テスト

- 100、500、1,000同時受講者
- 1秒間に500イベントのバースト
- 証跡アップロード失敗時の再送と重複排除
- WebSocket再接続、順序逆転、イベント欠落回復
- 管理画面P95、アラート反映時間、キュー滞留時間

## 4. セキュリティテスト

- テナント越境アクセス
- 権限昇格、IDOR、CSRF、XSS、SQL Injection
- 署名URLの期限、再利用、推測耐性
- 監査ログの改ざん・欠落
- 顔特徴量・画像のログ混入
- CSV式インジェクション

## 5. UI受入

- 1366×768、1440×900、1920×1080
- iPad横・縦、主要ブラウザ最新版
- 200%文字拡大、キーボード操作、コントラスト
- ライト／ダーク、長い氏名、長い研修名、日本語／英語
